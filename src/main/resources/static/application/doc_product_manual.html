背景

背景 目标 架构 部署 数据库表 EL表达式

1. 云平台迁移项目

随着行内云平台应用迁移项目开始实施，外围和后线OLAP类系统急需一个能在x86平台上运行的，自动化程度较高，且高可用的作业调度工具。

将应用从小型机迁移到x86平台后，应用服务器的数量成倍式的增长，单节点的资源有限，因此作业的调度执行需要支持分布式。

在云平台项目实施过程中，目标应用的子系统或模块较多，用户希望能有一个具有集中式管理的统一调度平台，当新增一个子系统，只需将一个新的服务器节点纳入调度平台统一管理，并实现资源隔离的目的。

2. MPP架构数据库在行内的推广

2018年经过总行选型，确定GBASE为MPP数据库供应商.

架构

背景 目标 架构 部署 数据库表 EL表达式

调度工具的开发采用Zookeeper + RDB + OSGi等技术组件或规范，以插件开发应用模式， 在任务负载均衡，作业类型适配，基础服务等方面提供热部署及动态配置切换。Zookeeper提供分布式节点管理和插件服务注册，任务的配置信息和运行信息存储在RDB当中，目前支持MySQL和Oracle数据库，对于Job运行时热点表，应用采用分片技术，极大提高作业调度的效率。

灵活简单分布式作业调度

渐进式基础开发框架，为作业的调度或执行提供更多的服务支持。

  Scheduler ：
    集群管理，任务驱动，负载均衡，信息采集，计划任务
  Slaver ：
    任务执行，插件注册，计划任务
  Registry ：
    插件注册中心，分布式锁，节点及插件注册，Master选举

方案一: 简单部署（单机）

单机模式部署

无高可用要求，单一产品作业量不多的情况，建议1台数据库服务器，1台调度服务器，1台Zookeeper服务器。

  WWSMaster ：
    启动两个进程，批量进程和WEB控制台进程。批量进程即执行调度计算，也执行具体的作业任务，因此会有相互影响可能。
  Zookeeper ：
    单机部署，也可集群部署，3-n个节点，n为大于3的奇数
  DBServer ：
    数据库服务器，支持MySQL和Oracle数据库

方案二: 高可用部署（集群）

集群模式部署

要求高可用，多产品作业量较多的情况，建议2台数据库服务器，3台（或更多，根据作业执行压力自行适当增加Slave节点）调度服务器（WebConsole不考虑高可用情况），3台Zookeeper服务器。

  WWSMaster ：
    启动两个进程，批量进程和WEB控制台进程。批量进程即执行调度计算，也执行具体的作业任务，因此会有相互影响可能。
  WWSSlave ：
    执行某一个产品或模块具体作业的服务器节点。
  Zookeeper ：
    最少3个节点，或3-n个节点，n为大于3的奇数
  DBServer ：
    数据库服务器，支持MySQL和Oracle数据库，

1. 端口使用说明

WWS运行时，需要开放 1099 44444 8101 8585四个端口，其中 1099 44444为调度集群各节点间JMX通信端口； 8585为WebConsole绑定端口； 8101为字符终端命令行端口。

请在启动前确认端口是否被占用，如果上述端口已被其他应用占用，安装时，将修改更多配置文件。

3. ZOOKEEPER配置调优说明

参数调优

鉴于以下三种情况，会导致wws进行停止，所以建议修改zookeeper的配置文件，调整seession的timeout值和快照机制：

  1） 网络抖动，导致wws与zookeeper的session超时

  2） zookeeper的负载过高（比如aof时间过长），导致wws与zookeeper的session超时

  3） wws进程虚拟机负载过高（线程太多、GC）,导致心跳响应超时

如果zookeeper为多个应用共同使用或者zookeeper上写入的数据太大时，更应该考虑调整参数设置，具体操作如下：

#进入zookeeper安装目录，找到/usr/local/zookeeper/conf/zoo.cfg文件(位置因环境而异)，确认文件中是否含有：
# minSessionTimeout ： 最小的客户端session超时时间，默认值为2个tickTime，单位是毫秒
# maxSessionTimeout ： 最大的客户端session超时时间，默认值为20个tickTime，单位是毫秒
minSessionTimeout=10000
maxSessionTimeout=60000
# 优化快照机制
autopurge.purgeInterval=2
autopurge.snapRetainCount=10
snapCount=1000000
# 允许的客户端连接数量
maxClientCnxns=2000

增加zookeeper JVM堆栈内存

#进入zookeeper安装目录，找到/usr/local/zookeeper/conf/java.env文件(位置因环境而异)，确认文件是否存在，不存在则创建
touch /usr/local/zookeeper/conf/java.env
# 写入内容,注意jdk路径需要根据环境而定
#!/bin/sh
export JAVA_HOME=/usr/local/jdk
export JVMFLAGS="-Xms2048m -Xmx4096m $JVMFLAGS"
# 重启zookeeper，查看进程确认是否堆栈大小是否调整成功
ps -ef|grep zookeeper|grep "-Xm*"

访问控制配置

安全级别较高的应用系统，由于信息安全要求，需要对zookeeper进行ACL设置，WWSF可通过配置的方式支持ACL，如果zookeeper为WWSF独占可按照以下步骤设置ACL

（缺省配置为两个Digest用户wwsguest和wwsadmin，其中wwsguest只有read权限，默认密码“wg!2019”，wwsadmin拥有所有权限，默认密码“wa!2019”）:

首先我们必须将zookeeper的根节点和缺省节点（znode）都需要进行ACL设置

  #登陆zookeeper客户端执行如下三条命令，其中密码必须进行SHA1-BASE64编码处理

  setAcl / digest:wwsguest:PUyozWsnHJAl+xQhqjYULQw46kM=:r,digest:wwsadmin:ZDJILJg2sY8ftjC2ZZ3QtPQ5V7w=:cdrwa

  setAcl /zookeeper digest:wwsguest:PUyozWsnHJAl+xQhqjYULQw46kM=:r,digest:wwsadmin:ZDJILJg2sY8ftjC2ZZ3QtPQ5V7w=:cdrwa

  setAcl /zookeeper/quota digest:wwsguest:PUyozWsnHJAl+xQhqjYULQw46kM=:r,digest:wwsadmin:ZDJILJg2sY8ftjC2ZZ3QtPQ5V7w=:cdrwa

  #密码加密处理，可在ZOOKEEPER安装服务器上执行如下命令获取，注意ZOOKEEPER安装路径，版本因环境而异

java -cp d:/Program/zookeeper-3.4.6/zookeeper-3.4.6.jar;d:/Program/zookeeper-3.4.6/lib/slf4j-api-1.6.1.jar \
org.apache.zookeeper.server.auth.DigestAuthenticationProvider \
<user>:<password>

也可使用openssl命令

echo -n <user>:<password> | openssl dgst -binary -sha1 | openssl base64

  #使用zookeeper的自带客户端登陆，进入客户端后，执行如下指令，然后才能进行已授权的相关操作了：

  只查看数据（r）：

  addauth digest wwsguest:wg!2019

  操作数据（cdrwa）：

  addauth digest wwsadmin:wa!2019

  #如何在wwsf中设置ACL：

  修改批量程序中配置文件 etc/wws.cfg，设置参数zoo.acl.string值：“31,wwsadmin:wa!2019/1,wwsguest:wg!2019”

  修改WEB程序中application.properties文件，设置参数zoo.acl.string值：“31,wwsadmin:wa!2019/1,wwsguest:wg!2019”

  #如何在wwsf中取消ACL：

  修改批量程序中配置文件 etc/wws.cfg，注释掉参数zoo.acl.string

  修改WEB程序中application.properties文件，注释掉参数zoo.acl.string

  修改后需重启批量和WEB服务

4. WebConsole服务安装

wws WebConsole为基于BS的管理控制台，建议资源足够时，也可独立部署。安装包目录结构如下：

  • lib    --基础Java类库存放目录
  • logs    --日志存放目录
  • release    --程序下载包路径，当作为主站时，可将安装包放在此目录，作为应用安装时，无需操作此目录

  • console.bat    --win平台启动应用

  • cryptor.bat    --win平台敏感信息加解命令，用于加密application.properties中密码等敏感信息
  • cryptor.sh    --linux平台敏感信息加解密命令
  • logback.xml    --日志打印设置
  • stop.sh    --linux平台停止应用

配置文件/wws/console/application.properties中配置项说明

在2.X版本中配置文件application.properties分割成了三个配置文件：app-api.properties；app-console.properties；app-comm.properties。但配置项几乎一致。

属性 必填 含义 描述
server.port 是 web访问端口 默认8585访问端口。
file.releasePath 是 wws版本包存放目录 此目录为绝对路径，指向webconsole安装目录下的release目录即可。
spring.datasource.driver-class-name 是 数据库驱动类 MySQL：com.mysql.jdbc.Driver
ORACLE：oracle.jdbc.OracleDriver
spring.datasource.url 是 数据库jdbc连接字符串 MySQL：jdbc:mysql://127.0.0.1:3306/wws?characterEncoding=utf-8&allowMultiQueries=true
ORACLE：jdbc:oracle:thin:@127.0.0.1:1521:ora_wws
spring.datasource.username 是 数据库用户名 如果调度独立数据库，可使用wws作为用户名，如果与应用库共用，则使用应用库的用户名
spring.datasource.password 是 数据库密码 数据库密码，密码明文和密码密文都支持
spring.datasource.initialSize 是 数据库线程池初始化连接数 默认为5个，一般不需要修改
spring.datasource.maxActive 是 数据库线程池最大连接数 默认为20个，一般不需要修改，当webconsole访问的人数较多时，可适当增加
zoo.connect.string 是 Zookeeper连接字符串 集群连接串，zookeeper配置ip和端口号，多个节点请使用逗号隔开
单机环境配置：例‘22.19.8.10:2181’
集群环境配置：例‘22.19.8.10:2181,22.19.8.11:2181,22.19.8.12:2181’
zoo.namespace 是 调度在Zookeeper上命名空间 与调度master节点的my.name相同，默认值wws，当一个zookeeper实例被多套wws集群使用时，需修改此值。
zoo.acl.string 否 zookeeper访问控制 如果zookeeper不做访问控制，可注释掉该参数，如果需要则可设置默认值（31,wwsadmin:wa!2019/1,wwsguest:wg!2019）
wws.jmx.user 是 webconsole连接master节点的jmx用户名 一般无需修改
wws.jmx.password 是 webconsole连接master节点的jmx密码 一般无需修改

5. 快速安装master节点和slave节点

通过WebConsole（http://22.188.9.60:8585）菜单（代理服务器/服务器）自动安装master或slave节点。

服务器指master节点或slave节点。

点击菜单【代理服务器/服务器】，打开服务器管理界面。

可以根据产品、节点编号和标签，查询服务器。

服务器管理界面，选中服务器列表前复选框，可进行如下操作：

        新增：新增节点信息（不需选中服务器列表前复选框）；

        修改：修改节点信息（状态值为未安装或安装失败，才可修改）；

        删除：删除节点信息（状态值为非联机，才可删除）；

        安装：安装节点（状态值为未安装或安装失败，才可安装）；

        卸载：卸载节点（状态值为脱机，才可卸载）；

        启动：启动节点（状态值为脱机，才可联机）；

        停止：关闭节点（状态值为联机，才可脱机）；

        线程资源信息：可查看调度线程资源信息和插件线程资源信息（状态值为联机，才可查看线程资源信息）。

属性 必填 含义 描述
node.id 是 节点编号（字母，数字，下划线组成的字符串） wws集群中，为每一个节点分配的唯一逻辑编号，建议采用‘产品_IP短地址识别‘，请使用字母，数字，下划线组成唯一节点标识，master节点请使用10000作为编号，master备机节点使用20000作为编号。

1.ww_job

在WWS中配置作业有两个概念：Job和Task，他们都可以理解为任务，Job为一项具有相对独立性的任务。在范围上比Task要大 ，代表的是一项目标，我们更关注于他的完成状态。如：12张财报加工核心C64表加工.
字段名 中文名 数据类型 字段说明
job_id job模板编号 String job模板编号唯一，不允许重复，主键约束。由数字，大小写字母，下划线组成
product 所属产品 String job模板从属产品
job_name 中文名称 String 中文名称
job_mode 模式 int 1-网状模型，2-网维模型
schedule_rid 调度资源编号 String 通常情况，启动Job实例后，调度会为实例分配一定的独享线程资源进行调度，实例完成后回收。如果在此设置调度资源编号，此Job模板产生的所有实例都将使用同一份调度资源，并且不会销毁。一般用于短，频，快的任务
title 标签 String 可配置多个标签，前后以逗号隔开
version 版本 String 版本号
create_time 创建时间 Date 创建时间，默认系统时间
creator 创建者 String job模板创建者

2.ww_task

范围比Job小的一种作业，同一个Job下可以配置多个Task作业.
字段名 中文名 数据类型 字段说明
job_id Job编号 String job模板编号，由数字，大小写字母，下划线组成
task_id Task编号 String 同一个job下，Task编号唯一，不允许重复,由数字，大小写字母，下划线组成
task_name task中文描述 String 中文名称
title 标签 String 标签,可配置多个,前后需逗号隔开
task_plugin 执行插件 String task任务插件
program_name 执行应用程序 String task程序名称，与插件名称不一致时，会根据插件名称和程序名称从ww_parameter获取公共参数，可视为通用参数配置，固化某插件的一部分参数值
allowed_rerun 故障后是否需自动重新执行 int 默认值0，当故障节点任务接管时，正在执行的任务将不会重新运行，而被置为‘需人工干预’状态；当设置为1时，故障节点任务接管时，无论任务处于何种状态，都会被重新执行。
period 周期 String task执行的时间（系统时间或自然时间）区间
working_day 工作日设定 String 配置task假日编排计划。需要与WW_CALENDAR配合使用，可以让TASK在你预期的工作日才执行，非工作日直接忽略通过，不执行作业逻辑，也不影响整个流程的执行。
error_delay 错误延迟执行时间间隔 int 出错时延迟执行的时间，单位秒，只有在error_max_num等于0或大于1时才生效，如果配置为0，系统视为未配置，则系统会默认30秒延迟执行时间。
error_ignore 是否错误忽略通过 int 当作业出现错误，而error_ignore值为1时，会忽略错误通过，让整个流程继续往下运行。默认为不忽略错误
error_max_num 错误最大尝试次数 int 任务出现错误最大重复执行次数，0为重试n次，直到任务成功为止；1为只执行一次，失败即task失败；大于1为重试执行设定次数，执行成功终止，或重试设定次数都失败后任务失败。
use_job_dimension 是否使用job模板默认维度配置方案 String 默认不使用
agent_scope 指定可执行的代理节点范围 String 设置task可执行节点范围，后续调度在此节点范围内，选择节点发送任务
create_time 创建时间 Date 创建时间，默认系统时间
creator 创建人 String 创建人
point_x X坐标 int 图形编辑界面task显示位置的坐标点x
point_y Y坐标 int 图形编辑界面task显示位置的坐标点y
